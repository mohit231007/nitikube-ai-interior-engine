# NitiKube Whole-Home Optimization Contract

The whole-home optimizer answers a constrained selection question:

> Given a set of candidate design packages for every room, which one package per room produces the best user-defined utility while respecting verified geometry, must-not-compromise policies, locks, reserve and the total home budget?

It is **not** permission for an AI score to override a physical or financial constraint.

## Hard constraints first

A room option is removed from the optimizer before scoring if it fails a hard rule such as:

- marked infeasible by an upstream engineering/material/procurement check;
- minimum room area;
- minimum room width/height when supplied;
- room-level maximum cost;
- minimum quality/durability/comfort/maintainability policy;
- a required feature/tag;
- explicit homeowner lock to another option.

If an option requires a room dimension and that geometry is unavailable, the fit check is `unknown`, not an assumed pass.

## Ranking inputs

The current additive utility dimensions are:

```text
quality
durability
aesthetics
comfort
maintainability
```

Each score is constrained to `[0, 100]`. These scores are **ranking inputs**, not automatically scientific facts. Their source should be visible (`user`, sourced evaluation, future evidence model, etc.).

Weights are explicit and normalized before use:

```text
utility(option) = Σ metric_i × normalized_weight_i
```

The home objective is the sum of selected room utilities.

## Cross-room budget coupling

The optimizer selects exactly one feasible option for each required room. It therefore handles trade-offs that independent room ranking cannot.

Example:

```text
Living premium = ₹700
Living value   = ₹400
Bedroom premium = ₹700
Bedroom value   = ₹400
Whole-home spendable budget = ₹1,100
```

Choosing both premium options would cost ₹1,400 and is invalid. The global optimizer can instead choose one premium + one value option for ₹1,100.

## Protected reserve

The user can protect a reserve before design selection:

```text
spendable_budget = total_budget - reserve
```

The optimizer never consumes the reserve. `budget_remaining` is reported against the full budget, so it includes the protected reserve plus any unspent design budget.

## Exact Pareto-state pruning

The implementation uses dynamic programming across rooms. After each room, intermediate states are pruned by cost and additive utility.

When all states have selected an option for the same set of rooms, state A dominates state B when A:

```text
costs no more
and
has utility no lower
```

A dominated state can never become optimal after adding the remaining rooms, so it can be safely discarded. This gives an exact result for the current additive objective while avoiding the full Cartesian-product explosion in common cases.

## Locked choices

A homeowner can lock an option for a room before re-optimisation. A lock becomes a hard constraint. If the locked option is missing or infeasible, NitiKube returns an explainable infeasible result instead of silently replacing the choice.

## Value / Balanced / Full-budget scenarios

The UI can rerun the exact same hard constraints at multiple user-specified budget fractions. The fractions are visible scenario envelopes, not NitiKube claims about what a home *should* cost.

For example, the user may choose:

```text
Value       = 75% of total budget
Balanced    = 90%
Full budget = 100%
```

Each scenario has its own protected reserve fraction and produces a separately optimized room selection.

## Verified geometry bridge

The Streamlit whole-home page imports the `nitikube.verified_geometry` document generated by the Verified Geometry Editor. Room areas/bounds therefore come from the authoritative user-verified geometry layer rather than raw CV proposals.

Future room planners can generate candidate packages automatically from this same geometry schema without changing the cross-room optimizer.

## Current boundary

The optimizer currently **selects among candidate room packages**. It does not yet generate every candidate package from scratch.

The next generation layer must combine:

1. verified room geometry;
2. room function and household/lifestyle needs;
3. ergonomic/circulation constraints;
4. climate/design pressures;
5. material suitability evidence;
6. product/procurement evidence;
7. lighting/building-physics checks;
8. subjective style preferences.

Only candidates that survive the relevant deterministic/evidence checks should reach whole-home ranking.
